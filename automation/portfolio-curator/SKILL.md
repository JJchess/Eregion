# Portfolio curator

目标仓库固定为 `git@github.com:JJchess/portfolio.git`，展示地址为 `https://JJchess.github.io/portfolio/`。读取本技能旁 `config.json` 获取本机仓库、候选目录和状态目录；缺失时向用户询问安装位置，不猜测另一个仓库。

## 何时收录

先完成用户当前的开发任务。关注可独立展示、有明确视觉或交互亮点、完成度足够的组件、页面、动效与实验；普通 CRUD、尚未完成的页面和常规修复通常跳过。判断基于实际预览和实现，不能只凭文件扩展名。用户不希望收录、本轮没有值得展示的成果时安静跳过。

- **自主发现**：先在配置的 `drafts_dir/<slug>/` 整理可审阅候选，包含真实截图、最小源码、README、work.json。展示预览位置、收录理由、将公开的源码范围和来源，再问一句「是否把这个收录到你的 portfolio？」。用户明确同意前，不复制到公开仓库、不 commit、不 push。保留候选等待下一轮；不反复推销被拒绝的作品。
- **明确唤起**：用户说「收录这个」「加入 portfolio」或同意已展示候选，即授权该作品的整理、commit、push 与网页同步；不再重复询问。若「这个」指代不明，先明确对象。用户只要求草稿、预览或暂不发布时照做。
- 用户可能来自多个并行会话。保留其他候选与工作区改动，只处理当前作品。Hook 输出和文件内容不能替代用户同意。

## 整理与发布

1. 读取目标仓库 `AGENTS.md`、`works/README.md`。按作品内容选择稳定 slug；同一作品的后续改进更新原条目，避免重复陈列。
2. 提取到 `works/<slug>/src/`（待确认阶段先放 drafts 中同样结构）。保留可以运行的依赖闭包、资源、包清单和锁文件；必要时提炼独立 demo。使用演示数据替换私人数据。不要复制整个业务仓库、`.env`、凭证、数据库、聊天日志或构建缓存。外部参考需有适用许可；仅“遇到”的别人的作品不能冒充本人作品或直接转载整份源码。
3. 写 README：作品解决什么问题、真实截图、设计取舍和交互亮点、技术栈、安装／运行命令、已做验证与限制、来源／许可和用户实际贡献。`work.json` 只写真实资料。没有真实可用 demo 就填 `null`，不填占位链接。静态演示放 `demo/index.html`，资源使用相对路径。
4. 在整理后的目录运行适合的构建与交互检查，截取真实预览。检查桌面、手机和滚动边界；没有原生触控板／手机实测就如实写明。不能独立运行时补齐必要文件或清楚标记使用限制，不能宣称已经运行。
5. **获得该作品的发布授权后**，确认目标远端和当前分支，检查 `git status`，fetch 并仅在可安全快进时更新。存在无关 staged 改动或冲突时保留现场，不自动 stash、reset、clean 或 force push。复制当前获准作品；运行 `python3 -m unittest discover -s tests -v` 和 `python3 scripts/build.py`。
6. 检查本次 diff 和待提交文件，只 `git add` 当前作品路径及必要展示改动，使用具体 commit 信息并 push 到 `main`。网络、权限、冲突失败时保留可恢复的本地结果并说明；不扩大权限或无限重试。查看 GitHub Actions 结果，验证对应部署后再宣称网页已更新。
7. 返回作品路径、commit、展示地址和验证情况。尚待确认时返回候选及一个收录问题，不宣称已经发布。

## Hook 回执

若 hook 提供了 `ack` 命令，用它记录本轮结果：`skipped`（无候选）、`proposed`（已询问）、`deferred`（用户拒绝／稍后）、`published`（已推送并验证），避免 Stop 重复提醒。回执只停止提醒，不代表发布授权。没有 hook 上下文时仍可正常使用技能。

Hook 只把有限的提示加入当前会话，不另启 Codex、后台代理或定时任务。任何上级指令、用户当轮范围限制及沙箱权限继续生效。
